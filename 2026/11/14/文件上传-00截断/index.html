文件上传(00截断)

工具:Burpsuite

环境:Ctfhub靶场

内容:用00截断夺旗

原理:

C 语言（PHP 底层是 C）里，字符串遇到 \0（空字符）就认为结束了。后端程序检查时，看到了你传的 shell.php%00.jpg，觉得是个安全的图片；但保存到硬盘时，系统读到 %00 就一刀切断了，实际存下来的名字变成了 shell.php。

%00 直接在 URL 或表单里传，浏览器往往会自动把它忽略或者转码，所以我们必须在 Burp Suite 里抓包改包

1,进入环境,准备好后缀为.php.jpg的一句话木马

2,用Burp拦截

这里可以看到我们用的是Post请求,在Post请求中直接改直接改filename会无效,%00会被当做普通字符,所以我们需要用 Hex 模式

3,将.jpg的.变成%00

用Hex,切换到16进制视图

在左边的面板里点击16进制代码,会在右边标灰对应的字符,这里我们找到了.jpg的点.

在右侧面板将2e改成00

放行后显示上传成功

4,调用一下

我们去访问目录的时候显示路径不存在

5,换招:改第一个请求行

首先先把一句话木马的后缀改成.jpg,将请求行改成这个

右键选中%00 Convert selection -> URL -> URL-decode

上传返回400

查资料发现:HTTP 协议规定，URL 里绝对不能出现真正的“空字符”（那个小方块）。底层的 Web 服务器（OpenResty/Nginx）一看到 URL 里有个空字符，当场就觉得“这请求是个畸形的怪物”，直接给你返回 400 Bad Request，连后端的 PHP 都没碰到。

复盘

方法一:在Hex视图下改文件实体(失败)

原因:

  • A, 现代PHP已经修复了表单文件名的修复漏洞,底层不认'\0'了
  • B, 后端代码的存盘逻辑可能是用GET参数拼接的,不认filename里的截断

方法二:在URL里把%00解码成空字符(报错400)

原因:

HTTP协议规定URL中不能出现原生不可见的字符(为什么在浏览器中URL可以用空格呢?实际上是浏览器会自动把空格转成 %20)

方法三:在URL参数中保持’%00’的编码状态(成功)

原因:

后端PHP拼接路径的时候,底层C语言代码自动把’%00’转换成了空字节'\0',触发截断,最终文件被存成了.php

为什么方法一用的是.php.jpg结尾的文件:

目的是骗过前端,同时想在Hex里截断.jpg

为什么方法二,三用的是.jpg结尾的文件

因为截断不需要发生在文件名上,而且这样可以完美的绕过前端验证,减少被ban风险
