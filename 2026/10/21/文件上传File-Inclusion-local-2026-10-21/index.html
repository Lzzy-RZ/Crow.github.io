文件上传(client check)

工具： Burp Suite、curl
环境： 本地 Pikachu 靶场
目标： 验证文件上传客户端（前端）校验绕过

漏洞原理

用户选择文件时，浏览器会检查文件扩展名。选择其他类型的文件时，前端 JavaScript 会直接拦截，请求不会发送出去。

因此可以先用图片后缀让请求成功发出，再在 Burp 中把文件名改回原来的后缀。如果服务器没有再次校验，而且上传目录能够执行 PHP 代码，就说明服务器可能被控制。

操作步骤

1. 进入本地靶场

打开 Burp Suite 自带的浏览器，进入本地 Pikachu 靶场。

页面提示仅允许上传图片。

2. 观察上传请求

打开 Burp Suite 的 Intercept，上传一个 .png 图片，查看请求结构。

确认浏览器通过 multipart/form-data 接收并发送文件。

3. 修改后缀并验证服务器行为

将请求发送到 Repeater，把文件名后缀从 .png 改为 .txt，然后点击 Send。

请求返回 200，页面也没有出现拒绝提示，说明拦截主要发生在前端。后续还需要确认文件是否真的保存到了服务器。

4. 验证上传文件

刷新页面后，页面给出了文件保存路径。直接复制并访问这个路径。

成功返回了刚才发送的图片，说明服务器没有对上传文件类型进行严格限制。
